# Worst Hotel Ever

Кооперативный отель от первого лица для Windows. Unity 6000.3.2f1 / C# / URP.

Текущая линия разработки: **1.1.1-ui-alpha1**. Компактный контекстный HUD и бумажный журнал дежурного вместо постоянных технических панелей. Подробности открываются по запросу; срочная угроза остаётся заметной. Механики опасных смен сохранены: три вида аварий, предупреждения и изоляция, здоровье, спасение и смерть, ограниченные аптечки, выбор риска, победа/провал и восстановление команды. Четыре стартовых и два приобретаемых номера, гости и запросы, брони, многодневные проживания, экономика и покупки. Это экспериментальная итерация на пути к релизу: внешний парный тест и проверка удобства/интересности людьми ещё необходимы.

Откройте папку `Worst Hotel Ever` в указанной версии Unity. Запустите `Tools/Build-Windows.ps1` из PowerShell: тесты выполнятся перед Windows-сборкой в `Builds/Windows`. Для игры на другом ПК нужна вся эта папка, не только EXE. Сборки, Library и результаты отдельных запусков не хранятся в Git.

Для новой UI-версии: `Tools/Build-Windows.ps1 -Ui` → **`Builds/WindowsUI`**. Проверка: `Tools/Test-UICandidate.ps1`, итог `TestResults/ui-candidate-results.txt`. Старые `Builds/Windows` и выданные ZIP не перезаписываются. Перед обычной игрой закройте старую версию: новый `PLAYTEST_DANGER.cmd` продолжает тот же тестовый отель, и два хоста не должны писать его одновременно. `-PreserveLiveDangerSession` у тестового скрипта явно исключает только проверку неизменности занятого danger-слота; обычный и MVP-слоты проверяются, а сама оговорка записывается в отчёт.

Полная автоматическая локальная проверка: `Tools/Test-DangerCandidate.ps1` (или `-SkipBuild`, если текущая сборка уже готова). Включает прежние регрессии `Test-MvpCandidate.ps1` и новые проверки production-v3. Нужен доступный графический Windows-сеанс. Сценарии запускаются последовательно в отдельных тестовых слотах; итог — `TestResults/danger-candidate-results.txt`. Перед внешней приёмкой дополнительно просматриваются реальные снимки UI/мира. `PLAYTEST_DANGER.cmd` выбирает отдельный постоянный слот, не трогая основной отель и прошлый MVP-плейтест.

Прямой кооператив проверяется локально несколькими процессами. Steam AppID 480 — только экспериментальный режим; проверка через интернет на двух настоящих ПК/аккаунтах остаётся обязательной. Это не коммерческий Steam-релиз.
