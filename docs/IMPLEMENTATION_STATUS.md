# Фактический прогресс pre-MVP

Начало: 22 сентября 2026. Основной план: ../WORST_HOTEL_EVER_MASTER_PLAN.md.

## Границы текущей сборки

Windows x64, первое лицо, 2 сотрудника, 4 номера, перенос предметов, гости/заселение/багаж/полотенца, уборка кровати и мусора, ремонт течи и отдельная уборка воды, деньги/итоги смены/улучшения, сохранение и продолжение. Стилизованные оригинальные процедурные модели. Steam-релиз не входит в pre-MVP.

## Среда

- Unity 6000.3.2f1 (6.3 LTS), установлен Windows Standalone Support.
- Уже созданный владельцем URP-проект: `Worst Hotel Ever/`; не переносим и не уничтожаем его исходные сцены.
- URP 17.3.0; Input System 1.17.0; NGO 2.7.0 (добавлен, проверка импорта впереди).
- GPU: NVIDIA GeForce RTX 2060 SUPER. Свободно на C: около 46 GiB при старте.

## Этапы выполнения

- [x] A. Воспроизводимая Windows x64 development-сборка. Unity 6000.3.2f1, Mono, DX11, 20 нативных сценариев перед сборкой. Исходная SampleScene не уничтожена.
- [x] B. Процедурный первый этаж: лобби, ресепшен, склад, четыре меблированных номера, персонажи и предметы. Первое лицо, клавиатура/мышь, настройки, контролируемая переноска.
- [x] C. Авторитетная сетевая сессия двух отдельных процессов NGO/UnityTransport. Подключение, реальные изменения предметов/комнаты, проверка прав, отключение и освобождение предметов проверены. Steam lobby/transport реализован отдельно; внешний интернет-тест НЕ выполнен.
- [x] D. Гости, очередь, заселение, багаж, полотенца, грязное бельё, мусор, ремонт и отдельная уборка воды, недовольство, задачи, выезд. Двадцать native-сценариев и реальное удержание E через клиент проверены.
- [x] E. Подготовка/смена/закрытие/итоги, деньги, три улучшения, пополнение, восстановление из плохой смены, атомарный save/backup, архив при новой игре. Проверены два дня подряд, коррупция primary, будущая версия и rollback при блокировке файла.
- [x] F. Выполнены нативные тесты, несколько прогонов двухпроцессного smoke, визуальная проверка EXE и независимый разбор интеграции. Путь готовой сборки: `Builds/Windows/WorstHotelEver.exe`; инструкция: `README_PRE_MVP.md`.

Это **pre-MVP**, а не выполнение всех этапов 00–19 и не заявление о готовности к продаже. Большие пункты мастер-плана намеренно не отмечены целиком: в них есть расширенные функции, отсутствующие в этой версии.

## Фактически проверено 22.09.2026

- `Tools/Build-Windows.ps1`: сборка успешна, 0 ошибок. Единственное предупреждение — отсутствие Unity Cloud token для загрузки отладочных символов; оно не мешает локальному EXE.
- `TestResults/simulation-tests.txt`: 20/20 сценариев внутри настоящего Unity (не mock JsonUtility).
- `Tools/Test-Coop.ps1`: PASS у хоста и клиента. Второй процесс действительно смещает авторитетную позицию, использует E на полке, получает полотенце, проверяет отказ покупки возле доски, бросает предмет Q, проходит физический маршрут в 102 и снимает бельё удержанием E. Хост видит кровать без белья, после disconnect освобождает грязное бельё, записывает и загружает результат.
- Проверены Input System → WASD → CharacterController → сеть, TAB/Escape, focus ray и timed work. Сетевой тест использует программно поданные события Input System; это не выдаётся за живой тест двумя людьми.
- Рендер настоящей URP-камеры проверен в готовом player; нет отсутствующих/pink shaders. `TestResults/host-hotel.png`, `client-hotel.png`, `client-room-102.png` — engine-rendered изображения, без HUD. Скрытое окно имело чёрный backbuffer, поэтому тест явно рендерит камеру в текстуру.
- Через компьютерный интерфейс запущен EXE, проверены меню, создание новой хост-сессии, вид от первого лица и штатное закрытие. В одиночной видимой сцене индикатор показывал около 89–90 FPS на RTX 2060 SUPER; это наблюдение, не системный benchmark.
- Повторно открыт новый процесс EXE, через «Продолжить» загружен созданный ранее пользовательский слот: день 1, 400 ₽ и состояние подготовки восстановлены. Проверен возврат к IP после отказа Steam; окно игры работает.
- Отдельно нажата явная кнопка тестового Steam-режима в готовом EXE: нативная библиотека загрузилась, Steam сообщил `NoSteamClient` (клиент Steam не запущен). Игра корректно вернулась в меню с причиной и возможностью IP. Вход в аккаунт, запуск Steam и создание внешнего лобби не выполнялись; online этим не подтверждён.
- Независимая задача нашла 1 P1 и 5 P2, передала воспроизведения. Исправлены: ложный save-success, уход после неудачной записи, панели после disconnect, различие UI/tasks, backup-only Continue, слабые сетевые assertions. Повторный статический проход подтвердил закрытие; новых доказанных P0/P1 в этих изменениях не найдено.

## Ограничения проверки

Локальный сетевой тест не доказывает NAT traversal/Steam internet. Нужен внешний тест на двух Windows-компьютерах с разными аккаунтами-друзьями Steam. Тестовый AppID 480 не является собственным AppID игры. Не выполнялись регистрация Steamworks, покупка AppID, принятие издательских договоров или публикация. Эти ограничения не скрываются за словом «готово».

В версии не реализованы: 3–4 игрока, host migration, голосовой чат, полноценная динамическая навигация/избегание, сложная свободная физика и стопки, кофе/ресторан, переселение гостя, большое разнообразие событий, многодневные бронирования и коммерческий арт/контентный объём. Перенос/тележка управляемые, комнаты и маршруты фиксированные, UI пока программный IMGUI. Смена по умолчанию восемь минут; баланс предварительный. Контроллер необязателен и не добавлен.

Первая неудача smoke была ошибочным тестовым путём сквозь складскую перегородку. После корректировки маршрута и усиления проверок получены PASS; ранний неуспех не скрывается и не выдаётся за игровую проверку всего уровня.
