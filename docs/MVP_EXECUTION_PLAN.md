# Переход 0.4 → полноценный внутренний MVP

Старт: 22.09.2026, исходная проверенная версия `7dcbb976187261c136c8e69a3977dcf89f3249f0`.
Поручение владельца: очень внимательно довести игру до полноценного MVP, с проверкой этапов.

## Граница результата

Авторитетный scope — раздел 5.4 и этапы 09–13 `WORST_HOTEL_EVER_MASTER_PLAN.md`, с оставшимися игровыми функциями срезки 08. Не подменять MVP следующим небольшим pre-MVP. Сохранения середины дня, уже работающие в 0.4, не сокращать. Windows, первое лицо, онлайн, два игрока обязательны.

Лифт/второй этаж, прачечная, voice, 3–4 игрока и Steam-магазин не входят во внутренний MVP по ранее принятым D02/D04 и разделу 5.5. Не считать их автоматически готовыми. Не оплачивать сервисы и не публиковать Steam-продукт без отдельного решения владельца.

22.09 владелец подтвердил возможность организовать второй Windows-ПК, другой Steam-аккаунт и человека для парного теста. До фактического результата внешний online и наблюдения людей остаются открытыми критериями; подготовить дистрибутив и воспроизводимый сценарий.

## Обязательная функциональная приёмка

- [ ] Четыре стартовых номера, физически доступные покупки 105–106; рост вместимости/маршрутов/спроса и сохранение.
- [ ] Tourist / Business / Family / VIP и Patient / Impatient / Messy / Demanding / Friendly действительно отличаются; требования вместимости и качества, неподходящий номер с объяснением.
- [ ] Полотенца, кофе, уборка, багаж; dirty towels, грязное/чистое бельё, мусор/полная корзина, вода; все названные инструменты и обе величины багажа.
- [ ] Sink / Toilet / TV / Lamp: местная поломка и износ отдельно от качества, вода/электричество отдельно от локального оборудования, одна utility-точка с физическим действием.
- [ ] Жалобы на фактическую грязь, оборудование, полотенца, ожидание, багаж, шум; эскалация/восстановление, переселение, компенсация без волшебного ремонта.
- [ ] Отзывы 1–5, репутация, три цены, фиксированный тариф действующего проживания, спрос по возможностям, сохранённый прогноз/бронирования/walk-in/отказ.
- [ ] Многодневный гость и party; брони на интервал без технического double booking, оплата ровно один раз.
- [ ] Восемь семейств улучшений, эффект белья/кофемашины, Bed / TV слоты, небольшой выбор отделки; недоступные/неэффективные покупки не продаются.
- [ ] Очередь/конгестия с выходом из блокировки, соседский шум, багажные ошибки и их исправление.
- [ ] Сохраняемый Director: нагрузка с дедупликацией первопричин, cooldown/anti-repeat, паузы/overload; Guest Rush, Walk-in Group, VIP Arrival, Minor Water Event; отдельная забронированная туристическая группа.
- [ ] Подготовка объединяет итоги/прогноз/цены/ремонт/снабжение/покупки; закрытие части номеров, небольшой долг и восстановление без обязательного нового отеля.
- [ ] Общий обзор Rooms / Guests / Operations / Schedule, понятные world-подсказки и сетевой ping.
- [ ] Версии контента/сейвов, миграция 0.4 и старше, атомарность/backup/ошибки IO, RNG без reroll через загрузку, bounded history/объекты.
- [ ] Не менее десяти дней с покупками, многодневными гостями, поломками, долгом и несколькими перезапусками процесса.
- [ ] Двухпроцессный ввод/конфликты/отключение/загрузка; проверка задержки и прав, реальные кадры Windows UI/мира.
- [ ] Проверка через интернет на двух ПК/аккаунтах и живой первый/повторный день, с записанными замечаниями и исправлениями.

## Последовательность реализации

1. Исследование точек расширения и договорённость о DTO/командах/координатах. До завершения дизайна — только чтение и этот план.
2. Стабилизировать контракт MVP и совместимость старых отелей; данные контента, проверки, границы сетевого снимка.
3. Расширить рабочие системы и физический отель: оборудование, кофе/инструменты, 6 номеров, инфраструктура, furnishing; интегрировать первую проверяемую сборку.
4. Добавить разнообразие, жалобы/переселение, цены/репутацию, многодневность/бронирования/прогноз; проверить переходы и сохранения.
5. Добавить нагрузку/события/группы, полный цикл подготовки и кризисное восстановление; проверять отсутствие бесконечных наград и роста объектов.
6. Завершить UI/подсказки/пинг/визуальные состояния всех новых систем; пройти обычное управление, не только команды тестовой модели.
7. Независимый review, native регрессии, десятидневные/многопроцессные сценарии, миграция, Windows build, визуальная проверка и исправления.
8. Выдать кандидат для внешнего парного online-теста. По результатам исправить блокирующие проблемы, повторить затронутые проверки и закрыть MVP только по фактической приёмке.

## Правила работы

Один процесс Unity Editor/сборки у интегратора; задачи работают в отдельных checkout с непересекающимися файлами и интеграцией проверенных коммитов. Не менять пользовательский `.vsconfig`, нормальный save и старые архивы. Каждый тест использует отдельный слот. Не переименовывать прототипные заглушки в готовые функции ради чекбокса. Материальные отклонения записывать здесь и в отчётах.

Промежуточные версии — контрольные точки, а не завершение текущего поручения. Полностью автоматические проверки не подтверждают удовольствие, звучание на слух или внешний Steam WAN.
