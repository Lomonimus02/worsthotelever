# Задачи разработки

Все задачи создаются по прямому запросу владельца. Общий источник решений — MASTER_PLAN и COMPONENT_CONTRACT. Не смешиваем worktree и не запускаем несколько Unity Editor.

- Интеграция / Windows EXE / сеть / первое лицо / UI: текущая задача `01a0c4ca-8d11-7ea0-8736-62c94735d137`, C:/Normal/Programs/Game.
- Логика / сохранение / модульные сценарии: `01a0c600-c1ce-7432-a3b8-4bfb934136ff`, отдельный worktree, отчёт docs/reports/simulation.md.
- 3D-отель / геометрия / визуальные состояния: `01a0c600-c1ce-7432-a3b8-4bdbcdfd8416`, отдельный worktree, отчёт docs/reports/world.md.
- Steam lobby/relay и проверка совместимости: `01a0c60b-4431-7793-8a03-86c1e843f04a`, отдельный worktree, отчёт docs/reports/steam.md. Прямое подключение по IP остаётся запасным вариантом.
- Независимая проверка интерфейсов, save/reconnect и качества smoke-тестов: `01a0c612-bf9e-7813-9b79-63a8fe67af7c`, отчёт docs/reports/qa-independent.md. Без конкурентного запуска Unity. Переданные находки интегратор исправляет и повторно проверяет.

Интеграция через проверку diff и cherry-pick конкретного коммита. Задачи не меняют файлы других компонентов без координации. Отчёты содержат ограничения и фактически выполненные проверки.

Итерация 0.2 повторно использовала существующие задачи логики и QA; новые дублирующие чаты не создавались. Логика передала контекстную помощь/навыки, QA — четыре проблемы отказоустойчивости и повторную проверку исправлений. Текущая задача интегрировала UI, recovery lifecycle, native/player/UI-тесты и Windows-сборку. План: ITERATION_0.2.md; итог: reports/release-0.2.md.

Итерация 0.3 использует те же задачи: логика владеет каталогом гостей, управляемым началом и модельными регрессиями; QA проверяет совместимость и достижимость шагов обучения; интегратор — интерфейс, новый сетевой протокол, standalone-прохождение двух дней и выпуск. План: ITERATION_0.3.md.

Итерация 0.4 повторно использует задачу визуала (выразительные состояния процедурного рига) и независимую QA (переходы snapshots, отмена и жизненный цикл эффектов). Интегратор отвечает за руки от первого лица, оригинальный синтез звука, настройки, native/standalone проверки и Windows-архив. Симуляция/сохранения/протокол не расширяются. План: ITERATION_0.4.md.

Внутренний MVP: прежние отдельные задачи передали operations, шесть помещений, сценарий двух ПК/сборщик диагностики и десятидневного бота. Дополнительные исполнители в основном checkout владели непересекающимися hospitality, pacing, UI и persistence; их совместная работа не является отдельными Git-worktree. После передачи файлов изменения заморожены, интегратор исправляет стыки и запускает Unity/игру. Независимые проходы проверяют чужие сетевые/input/lifecycle изменения только чтением, отдельный исполнитель расширяет opt-in player-тест новых физических сервисов. Общие решения и границы — MVP_COMPONENT_CONTRACT и MVP_EXECUTION_PLAN.

Опасные смены 1.1.0: переиспользованы четыре специализированных исполнителя в общем checkout, с раздельным владением файлами и явной заморозкой перед сборками:

- `01a0ca1f-523d-79f3-9c10-85ea36d79874` — правила опасностей, авторитетная симуляция и native-сценарии; последние регрессии отказа/меток завершены интегратором.
- `01a0ca2c-a6f6-7ff2-b585-85d23e232936` — v3-валидация, файловая миграция и сохранения; затем независимое чтение runtime-тестов.
- `01a0ca2b-75a4-7473-b331-3f620e143720` — input/UI/read-only представление; затем проверка сохранений и изолированное исправление отложенных жалоб с отдельными тестами.
- `01a0ca22-cc04-7970-a799-cdc6eab5a3fa` — мир, тела, оригинальный звук и обратная связь; затем независимое чтение симуляции и повторная проверка исправлений P1.

Интегратор владеет DTO/связями компонентов, production-фабрикой, протоколом, реальными Windows/сетевыми тестами, сборкой и упаковкой. Никаких конкурентных Unity/EXE со стороны исполнителей. Согласованные решения сохранены в `RELEASE_GAMEPLAY_PLAN.md`, `DANGER_COMPONENT_CONTRACT.md`, итоги проверки — `reports/qa-danger-alpha1.md`; завершённые исполнители закрыты после передачи результатов. Это не дополнительные Git-worktree и не заявление о проведённом внешнем человеческом плейтесте.
