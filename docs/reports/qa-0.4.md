## Найденные и закрытые замечания

### F01 — P2: старый клиентский снимок восстанавливал отменённую работу

Исходно `HotelFeedback.CancelWork` очищал только `work`. Вызов `Observe` до прихода подтверждения отмены снова записывал прежний `player.workTarget`. Последовательность «наблюдать грязную кровать и работу → отменить → наблюдать тот же старый снимок → получить пустой target и подготовленную напарником кровать» ошибочно давала `Complete`.

Исправление: `suppressWork` сохраняет локальную отмену через повторные снимки; новый явный `BeginWork` разрешает следующее наблюдение работы. Регрессия теперь вставляет и прежний объект хоста, и десериализованную клиентскую копию между отменой и результатом. **Закрыто по коду.**

### F02 — P2: локальная очистка стирала подтверждённый результат до наблюдения

Исходно `Observe` выполнялся после ввода. Если в кадре уже выполненной работы отпускалась E, открывалась панель или heartbeat возвращал «Сначала начните работу.», `StopWork` очищал ожидаемый результат и звук успеха пропадал. Одного переноса `Observe` наверх `Update` было недостаточно: клиентский сетевой callback мог вызвать ту же очистку до получения completed snapshot.

Исправление: результат наблюдается до обработки ввода; server-idle feedback теперь очищает только локальное намерение/heartbeat, сохраняя ожидаемый результат до следующего снимка. Явная отмена по-прежнему включает защиту F01. В standalone-сценарии добавлен вызов настоящего `Notify` до нового результата, несколько кадров со старым миром, затем завершение через heartbeat/ticks и отпускание E; ожидается ровно один `Complete`. Это детерминированная проверка порядка callback, не имитация полноценного сетевого канала. **Закрыто по коду.**

### F03 — P2: загрузка и доставка багажа тележкой оставались без звука

Исходный observer отслеживал только изменение `player.held`, но при обеих операциях с грузом в руках остаётся `cart_1`: меняется `bag.placedRoom`. После удаления безусловного звука из input-handler успешные операции тележки стали бесшумными.

Исправление: observer сохраняет два упорядоченных ID груза только для тележки, которую держит локальный игрок. Изменение груза даёт один `Item`; первый снимок, перестановка списка и чужая тележка остаются без сигнала. Соответствующие случаи добавлены в модельные проверки. **Закрыто по коду.**

## Остальные выводы

- Observer хранит скалярные значения: смена объекта клиентского снимка и изменение объекта хоста на месте не создают повторных событий. World/day/local-player baseline отделён от новых событий; отсутствие игрока и отключение сбрасывают наблюдение.
- Четыре пространственных источника течи и два локальных источника создаются вместе с девятью клипами при инициализации. Повторный Apply не создаёт источники/клипы; Silence обрабатывает recovery даже при оставшемся в памяти состоянии, а уничтожение компонента освобождает созданные ресурсы.
- Руки используют локальное намерение и подтверждённый target, отдельную настройку и нейтральную позу при остановке. Изменения жестов не добавляют покачивание камеры и не меняют авторитетную работу.
- В world-кандидате устаревший towelRequested не вызывает запрос после перехода из staying; недовольство и запрос сочетаются, возврат удовлетворённости восстанавливает выражение. Исходные transforms лица сохранены для предотвращения накопления смещения. Новые реакции не меняют навигацию, ноги, target ID или корневой коллайдер.
- Figure-тесты проверяют переходы стадий, сброс просьбы, плавность, ходьбу/перенос предмета сотрудником, сохранение иерархии/коллайдеров и неизменность JSON при World.Apply. Их наличие и содержание проверены чтением; результаты исполнения здесь не утверждаются.
- Относительно базы отсутствуют изменения в `HotelTypes`, `HotelSimulation`, `HotelSession`, `HotelSteam`, `HotelSaveStore`. Новые настройки принадлежат PlayerPrefs; схема сохранения и сетевой протокол не менялись.
