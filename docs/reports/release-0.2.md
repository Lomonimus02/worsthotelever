# Pre-MVP 0.2 — проверка и следующий игровой этап

22 сентября 2026, Windows x64 / Unity 6000.3.2f1 / Mono / DX11 / development build.

## Что изменилось

- Контекстная помощь первой смены: 8 освоенных навыков, общий прогресс команды, подсказка по предмету в руках/текущим гостям, ориентир направления и расстояния. Save v1 обратно совместим; skip/resume не меняет деньги и предметы.
- Читаемые причины невозможности заселения из тех же правил, что использует сервер. Уточнены подсказки кровати/ремонта/инструментов, владельца багажа, полотенец и занятости цели коллегой.
- Панель запросов и впечатлений гостя, подтверждение преждевременного завершения смены, управление продажами номеров у доски, повторный TAB закрывает задачи.
- После сетевого отказа роль хоста не определяет обязанность сохранять: последнее состояние записывается перед shutdown, при ошибке удерживается в памяти и доступно для повторной записи. Штатный выход/новая сессия не отбрасывает его молча.
- Одобрения подключения резервируют свободное место до завершения NGO approval. Заблокированный здоровый primary не считается повреждённым. Для зависшего Steam-запроса появилась явная кнопка сброса при остановленной сессии.
- Сборщик проверяет 32-символьные уникальные GUID метаданных; ожидание Unity не зависит от фонового licensing process tree.

Независимое code-review выявило четыре проблемы отказоустойчивости и ещё две проблемы интеграции/тестов; исправления повторно проверены по коду. Детали и честная граница работы ревьюера: [qa-followup.md](qa-followup.md).

- 29/29 offline Steam checks; 3 конфигурации компилируются с warnings-as-errors: Windows player, Windows editor, платформа без Steam. Включены 10000 случайных повреждённых пакетов; Steam не инициализировался.
- `Tools/Test-Session.ps1`, 18:32:15+: два инъецированных события TransportFailure проходят через действительный UnityTransport → NGO shutdown. Новые деньги после checkpoint сохранены; повторный хост загружает их. При реальном file-lock три ожидаемые ошибки записи (shutdown/disconnect/quit) не теряют состояние; после unlock retry успешно записывает его. Тест не заявляет физическое отключение роутера или Steam WAN.

Ровно один клиент принят с PlayerState, второй получает причину отказа; у хоста не больше двух участников. Сброс Steam проверен только по запрету в активной сессии и допустимости после остановки.
- `Tools/Test-Coop.ps1`, финальный клиентский отчёт 18:34:07: host PASS, client PASS. Реальные Input System events → WASD/CharacterController → авторитетная позиция, TAB/повторный TAB/Escape, E-перенос полотенца, клиентская подсказка по snapshot, host-only отказ у доски, Q, проход в 102, удержание E/heartbeat/снятие белья, отключение и сохранение результата хостом.
- `Tools/Test-UI.ps1`, 18:31:38: 14 реальных backbuffer-снимков для HUD, ресепшена, инспектора гостя, задач, управления, подтверждения конца смены и паузы, при 1280×800 и 960×600. Все просмотрены; исправлены мелкий текст причин и английский internal kind в очереди. Сам автоматический PASS означает ненулевой рендер, не полную визуальную QA.
- Через Windows UI отдельно проверены запуск EXE, меню 0.2, продолжение пользовательского отеля 0.1 (день 1 / 400 ₽), первая обучающая подсказка и штатное закрытие. Синтетический TAB через Windows automation не был принят raw-input окном; клавиатура проверена через настоящую Input System в player, а не выдана за живой человеческий прогон.
- Все fault/UI/co-op прогоны использовали отдельные `TestResults/smoke-save-<PID>.json`, не пользовательский слот.

## Найденные по пути ошибки проверки

Первая интеграционная сборка не включила новый test-файл из-за GUID длиной 33 символа. GUID исправлен, повторная native-сборка и все 33 сценария прошли. Первый UI-снимок скрытого окна имел чёрный backbuffer; тест теперь изменяет исходный размер окна перед обоими capture-разрешениями и проверяет ненулевой рендер. Эти ранние отказы не считаются успешными прогонами.

## Что остаётся открытым

Интернет/Steam между двумя реальными ПК и аккаунтами, полноценная проверка парой людей без объяснений, плохая/нестабильная сеть, настоящий зависший native lobby request, производительность на слабом железе, широкий набор разрешений/настроек доступности. Контекстная помощь ещё не управляет темпом первой смены; баланс и content scope не расширены. Новая версия не является коммерческим релизом или завершением всего мастер-плана.

Следующая итерация: сценарий первых двух дней и адаптивная учебная нагрузка, затем параметры типов гостей/запросов через данные. Внешний Steam-тест остаётся самостоятельным критерием готовности вертикальной срезки.

Для lifecycle сверены установленный исходный код NGO 2.7.0 и [официальный API NetworkManager](https://docs.unity3d.com/Packages/com.unity.netcode.gameobjects@2.7/api/Unity.Netcode.NetworkManager.html); окончательные выводы основаны на запусках этого player, а не только документации.
