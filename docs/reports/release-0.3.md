# Проверка выпуска pre-MVP 0.3

Дата: 22 сентября 2026, Windows x64, Unity 6000.3.2f1, Mono/DX11 development build. Основание: продолжение по просьбе владельца. План: `../ITERATION_0.3.md`.

## Что выпущено

- Управляемое начало нового отеля: регистрация, багаж, реальный дополнительный запрос, подготовка кровати, одна сохраняемая течь, ремонт источника и уборка воды, переход к обычному темпу. Работают один и два сотрудника; прогресс общий.
- Часы и сроки гостей не накапливают штрафы за задержку в освоении основ. Движение, работа и вода продолжаются. Подсказки можно скрыть отдельно; отказ от учебного темпа подтверждает хост. Смену можно закончить и до освоения основ.
- Каталог `Resources/guest-profiles.json`, три механически различающихся профиля и параметры запроса. Прибытие копирует значения в гостя; редактирование/исчезновение каталога не переписывает активный сохранённый профиль.
- План смены и помощь второго дня, объяснение удержанного таймера, повышение контраста UI и уведомления вне заголовка панели. Старые отели сохраняют прежний темп; клиентам нужна одинаковая версия протокола `WHE-premvp-3`.

## Проверки

1. `Tools/Build-Windows.ps1`: **49/49** сценариев в настоящем Unity — 20 исходных, 3 presentation/save-lock, 10 onboarding legacy, 16 Director. Финальная Windows-сборка: Succeeded, **0 ошибок**, одно предупреждение об отсутствии Unity Cloud access token для загрузки символов. Локальному EXE оно не мешает.
2. Новые native-сценарии: два дня соло; все уроки сотрудником 1; подготовка до открытия; долгие паузы 800/700/500 секунд без накопленного timeout; сохранение каждого этапа, в том числе незавершённой работы; отсутствие повторной течи/прибытия; оба фактических порядка одновременного окончания mop/sink; сухой остаток; opt-out и early finish; битый/отсутствующий каталог; неизменность активного профиля при правках; старый JSON без новых полей; защита future content от отката через backup; переназначение ушедшего гостя.
3. `Tools/Test-Opening.ps1`: PASS в готовом player. 600 секунд ускоренного ожидания первого гостя → заселение в альтернативный 103 → багаж → подготовка 104 → полотенце → течь → настоящие save/disconnect/reload → прежний профиль/цель → ремонт и вода → оплата → следующий день → физический второй toolbox → обычный день 2 → запись. Используются позиции фикстуры и ускоренные модельные часы; это не ручной плейтест.
4. `Tools/Test-Coop.ps1`: PASS обоих отдельных процессов. Проверены Input System → WASD/controller → сервер, TAB/ESC/E/Q/удержание E, владение предметом, работа в 102, отказ клиенту в административной смене темпа, профиль прибывшего patient и ClockHeld на клиенте, сохранение гостя и изменений комнаты у хоста после disconnect. Новый DTO проверяется реальной сетью, а не только локальной сериализацией.
5. `Tools/Test-Session.ps1`: PASS. Реальный NGO transport failure; последняя запись, сохранность живого мира при lock, запрет Quit/Disconnect(false) до успешного сохранения, retry после освобождения файла. Отдельно три процесса: хост + один принятый клиент + отказ лишнему с причиной; также проверена резервация двух одобрений в одном update.
6. `Tools/Test-UI.ps1`: PASS рендера, **22/22 снимка визуально просмотрены** в 1280×800 и 960×600 после повышения контраста. HUD, ресепшен, сведения гостя, задачи, управление, briefing, отказ от учебного темпа, early finish, pause, briefing/HUD второго дня. Текст и кнопки не обрезаны и не перекрываются. Автоматический PASS сам по себе не оценивает layout.
7. `Assets/Steam/Validation/Verify-Steam.ps1`: **29/29 offline checks**, три конфигурации компилируются с warnings-as-errors. Steam не инициализировался; внешний интернет этим не проверен.
8. Независимая задача проверила модель, сохранения, каталог, UI/harness и расширенные тесты. Подтверждённых новых P1/P2 в проверенном срезе не найдено. Полномочия и происхождение проверок разделены в `qa-0.3.md`.

## Что не утверждается

Не измерялась целевая длительность живой первой сессии 12–18/20–30 минут. Ускоренные тесты доказывают логику, но не веселье, понятность двум людям или реальную длительность. Сохраняется сокращённый pre-MVP без кофе, TV, ночующих гостей, полного бронирования, сложной физики, голосового чата и четырёх игроков. Полный этап 08 не закрыт.

Steam WAN на двух ПК с разными аккаунтами, host migration и коммерческий релиз не проверены/не выполнены. Публикации в Steam, покупки AppID и издательских действий не было. Следующий критерий качества — внешний совместный плейтест и настройка темпа/ощущения первого лица по наблюдениям, отдельно от дальнейшего расширения контента.
