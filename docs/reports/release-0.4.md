# Проверка выпуска pre-MVP 0.4

22 сентября 2026. Windows x64, Unity 6000.3.2f1, Mono/DX11 development build. База — 0.3, план `../ITERATION_0.4.md`.

## Результат

Четыре небольших процедурных жеста рук для белья, ремонта, швабры и мусора. Работа видна/слышна только при локальном намерении и подтверждённом target. Девять оригинальных синтезированных моно-клипов: шаг, прибытие, предмет, результат, четыре вида работы и течь. Два локальных и четыре пространственных источника переиспользуются, не создаются на каждый снимок. Починка источника выключает звук течи независимо от оставшейся воды.

Гости плавно переходят между ожиданием, просьбой о полотенце и недовольством. Просьба не теряется из-за недовольства и исчезает после смены стадии; возврат удовлетворённости восстанавливает лицо. Навигация, корневой коллайдер и прежний цикл ног не изменены. В настройках отдельно отключаются движения рук и течи, общая громкость 0 заглушает весь звук. Текст и прогресс работы остаются доступны.

Симуляция, сохранения, DTO и сетевой протокол не менялись: save v1, `WHE-premvp-3`. Для воспроизводимой совместной игры — одинаковая 0.4 у обоих. Смешанная пара 0.3/0.4 не тестировалась.

## Исправления при проверке

- Независимая QA выявила и повторно проверила закрытие трёх P2: старый snapshot восстанавливал отменённое ожидание; cleanup ввода/heartbeat и ранний server-idle feedback теряли результат работы; загрузка/доставка багажа тележкой не давала item cue. См. `qa-0.4.md`.
- Визуальная проверка интегратора выявила прежнюю ошибку: после отсоединения камеры её старые руки и предмет переживали disconnect. Риг удаляется, два материала рук переиспользуются и освобождаются владельцем. Регрессия проверяет один anchor, ноль Held visuals и пустые руки после reload.
- Новая кнопка сохранения настроек выходила за нижнюю границу Frame; отступы исправлены и повторно просмотрены в 1280×800 / 960×600.
- Первая версия визуальной фикстуры попадала не на того NPC: локальную тестовую телепортацию исправляла авторитетная позиция. Фикстура теперь устанавливает обе позиции и проверяет нахождение нужной фигуры в кадре. Это исправление теста, не игровой навигации.

## Доказательства

1. `Tools/Build-Windows.ps1`: **67/67 настоящих Unity-сценариев** — 49 прежних, 9 feedback, 9 figure. Сборка 0.4.0 Succeeded, 0 errors, одно прежнее предупреждение Unity Cloud access token при загрузке символов. Сгенерированное Unity включение Cloud в настройке проекта возвращено в исходное выключенное состояние.
2. `Tools/Test-Feedback.ps1`: PASS готового EXE. 6 источников/9 клипов; 100 повторных Apply без новых источников; две течи, ambient-off/on, ремонт с остаточной водой, master mute. Input System E запускает настоящую работу; gesture/audio активны, motion-off нейтрален, открытие панели отменяет без успеха. Отдельный порядок Notify(server idle) → старый мир → ускоренное завершение heartbeat/ticks → отпускание E даёт ровно один результат. Это детерминированная проверка порядка callback, не искусственный WAN-тест.
3. Та же проверка сохраняет/перезапускает хост: нет повторного прибытия, звуковых источников, рук или «призрачного» предмета. Снят кадр работы и пять кадров настоящего процедурного рига в изолированной визуальной фикстуре. Все шесть просмотрены; жесты различимы, старый carry больше не перекрывает NPC. Интеграцию World.Apply отдельно проверяют native-тесты с неизменностью JSON/targets/коллайдеров/объектов.
4. `Tools/Test-Coop.ps1`: PASS двух процессов, реальные Input System WASD/TAB/ESC/E/Q/held E → контроллер → сервер. Клиент заканчивает кровать в реальном времени, получает ровно один локальный completion, луп останавливается. Хост не присваивает чужой результат. Сохранились проверки прав клиента, profile snapshot, отключения и записи совместного результата.
5. `Tools/Test-Opening.ps1`: PASS двух дней, управляемого темпа, альтернативного номера, багажа/полотенца, кровати, течи, настоящего save/reload, ремонта/воды, выезда, покупки и следующей смены. Используются позиции фикстуры и ускоренные часы, не ручное прохождение.
6. `Tools/Test-Session.ps1`: PASS lifecycle и трёх capacity-процессов. Проверены реальный отказ NGO, emergency save, file lock, сохранность мира, запрет потери при Quit/Disconnect(false), retry после снятия lock, не более двух участников и явный отказ лишнему.
7. `Tools/Test-UI.ps1`: PASS рендера **24 снимков** в 1280×800 / 960×600, включая новые настройки. Настройки визуально просмотрены в обоих размерах; автоматическое получение остальных снимков не выдаётся за ручной просмотр каждого из них. Новые кнопки внутри панели, текст не обрезан.
8. `Assets/Steam/Validation/Verify-Steam.ps1`: **29/29 offline checks**, три конфигурации с warnings-as-errors. Без Steam initialization или online теста. Steam-код в этой итерации не менялся.
9. Source review отдельной задачи: APPROVE после исправлений; сама QA не запускала Unity. Нативное исполнение, финальные Windows-прогоны и изображения проверял интегратор.

## Ограничения и следующий критерий

Технические проверки аудиосэмплов/источников не заменяют оценку звука на слух: такой оценки не проводилось. Звуки пока процедурные, без музыки и озвучки. Нет измеренного долгого performance soak или пользовательской оценки удобства/веселья. Стены не выполняют акустическую окклюзию, звук течи затухает по расстоянию.

Steam WAN на двух настоящих ПК/аккаунтах, живой парный плейтест, voice chat, host migration, 3–4 игрока, полный MVP и коммерческий Steam-релиз не выполнены. Публикации в Steam и покупки AppID не было. Этап 08 мастер-плана целиком не закрывается: прежде чем резко расширять контент, нужен живой совместный первый сеанс и настройка темпа/ощущений по наблюдениям.
