## Поведение

`HotelWorld.Apply` передаёт только значения существующих `stage`, `satisfaction`, `towelRequested` в существующий `HotelFigure`.

- `queue` / `checkout`: гость держит руки перед собой на уровне пояса, слегка переводит взгляд и смещает вес. Оставшийся флаг полотенца не заменяет позу ожидания.
- `staying` + `towelRequested`: поднятая правая рука с небольшим движением, приподнятые брови, выразительный рот. После доставки полотенца жест плавно прекращается.
- `satisfaction < 45`: нахмуренные брови, изменённый рот, небольшой наклон головы и жест открытой рукой на уровне груди. При одновременной просьбе о полотенце поднятая рука сохраняется, а лицо остаётся недовольным.
- `walking` / `leaving`: устаревший запрос полотенца не вызывает жест просьбы. Низкая удовлетворённость остаётся видна по лицу. Широкие жесты ослабляются до нуля по уже существующему весу походки.
- `gone`, неизвестная или пустая стадия сбрасывают реакции; обычное удаление ушедших гостей в Apply сохранено.

Реакции смешиваются экспоненциально, без мгновенных смен поз. Лицо каждый кадр восстанавливается относительно сохранённых исходных значений, без накопления transform drift. Брови и рот используются из прежней геометрии. Новые GameObjects, материалы, UI, Animator, клипы, coroutine, таймеры событий и сетевые поля не создаются.

Существующие расчёты позиции, поворота, шага, ног и переноса/работы сотрудника сохранены. Корневая капсула, HotelTarget и авторитетное состояние не меняются. Только внутренние transforms модели получают позу. Камера не анимируется. Параметризованный `Animate(deltaTime, time)` содержит прежний LateUpdate animation path и используется также native тестами; LateUpdate передаёт обычные Time.deltaTime/Time.time.

## Визуальная проверка интегратору

В первой native/standalone проверке сравнить гостя в queue, staying с полотенцем, staying с satisfaction=0, сочетание двух последних состояний и возврат к нейтральному после доставки. Проверить читаемость поднятой руки и бровей с обычной FP-дистанции, затем проследить переход к walking/checkout/leaving. Нужна фактическая проверка кадров: амплитуды подобраны в коде, изображение и субъективная читаемость здесь не оценивались. Звук, save/network semantics и UI вне этой задачи.
