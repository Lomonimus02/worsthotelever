# Процедурный мир pre-MVP

Дата: 22 сентября 2026. Ветка: `codex/procedural-hotel-world`.

## Реализовано

- `HotelWorld.Build()`, `Apply(HotelState, ulong)`, `MakeItem(string)`, `MakePerson(bool, int)` и `HotelTarget.id/label` в одном независимом файле. Зависимости только UnityEngine и общий HotelTypes.
- Четыре номера 101–104, ресепшен, служебный склад, зона отдыха, короткое крыльцо, коридор с обозначением будущего расширения/лифта. Точные координаты основных целей берутся из HotelLayout.
- Кремовая штукатурка, деревянные панели с рейками и латунной отделкой, бордовые ковры, открытые дверные полотна, номерные таблички, окна со стилизованным пейзажем и шторами, текстовые вывески, растения, мебель, часы, мелкие следы износа. Геометрия имеет фаски, гранёные округлые формы и цилиндрические детали.
- В каждом номере: поперечно ориентированная кровать, тумба, светильники, умывальник с краном, зеркало, унитаз, TV, стойка полотенца, корзина мусора, багажная стойка. Есть реальные коллайдеры стен и крупной мебели.
- Состояние кровати 0/1/2, полотенце, мусор, протечка с падающими каплями, отдельная растущая лужа, улучшенная кровать и статус номера отображаются из RoomState. Ремонт течи не скрывает оставшуюся воду. Стойка и фактическое количество текстиля на складе реагируют на state.
- Все виды предметов: bag, toolbox, mop, linen, towel, dirtylinen, trashbag, cart. Чемоданы подписаны именем владельца. Груз тележки следует за тележкой и скрывается вместе с ней при локальном переносе.
- Четыре внешних варианта гостей, сотрудник в бордовой униформе, выразительные лица, глаза/брови/нос, аксессуары. Процедурные походка, дыхание, поворот головы, перенос и работа руками. Над гостями — небольшая табличка имени/запроса.
- Динамика кэшируется по ID. При каждом Apply меняются только transforms/видимость/необходимые надписи; ушедшие объекты удаляются отдельно. Локальный сотрудник и его held-предмет в мире скрыты; held colliders выключены. MakeItem подходит для отдельного first-person carry.
- Статическая архитектура батчится один раз; все изменяемые состояния и люди вынесены из static batching. Меши и палитра материалов общие для всех экземпляров.

## Материалы и ресурсы

Собственные shaders лежат в `Worst Hotel Ever/Assets/Art/Resources/Hotel/` и включаются в player через Resources. Нет зависимости от Shader.Find или отдельной настройки Always Included Shaders.

- `Resources.Load<Shader>("Hotel/HotelSurface")`: `_BaseColor` Color, `_Smoothness` float 0–1, `_Emission` float 0–2. UniversalForwardOnly работает и с Forward+/Deferred; предусмотрены ShadowCaster, DepthOnly и DepthNormalsOnly, main/additional lights, clustered lights и SSAO. Встроенная тёплая заливка сохраняет читаемость закрытых помещений без light bake.
- `Resources.Load<Shader>("Hotel/HotelLettering")`: шрифт TextMesh с depth test. Используется встроенный `LegacyRuntime.ttf`; textureRebuilt обновляет общий материал при перестройке атласа. Русские надписи — текст, а не растровые картинки.

Все добавленные модели/палитры/шейдеры/тексты созданы для этого проекта. Сторонние скачанные ассеты отсутствуют. Используются штатные API/ShaderLibrary установленного Unity URP и встроенный шрифт Unity. Отдельные сторонние лицензии не добавлены.

## Интегратору

- Ветка содержит только HotelWorld.cs, собственные shaders и этот отчёт. HotelTypes, сцены, пакеты и project settings не менялись. Unity-generated .meta создаст импорт проекта; здесь Editor не запускался.
- Сцену можно оставить пустой: `AddComponent<HotelWorld>().Build()`. Камера, FP input/carry, UI и сеть принадлежат интегратору.
- Источник координат — HotelLayout. Root/mesh предмета имеет pivot у пола. Для свободно лежащих предметов отображение прижимается к полу y=.025 вместо условной interaction-height из DTO; для доставленного багажа — к высоте стойки, для груза — к платформе тележки. X/Z сохранены. Simulated logical positions не меняются.
- У стойки есть настоящий collider x±1.2, z≈−1.07…−.33; NPC должны обходить её по маршруту через x≈1.7 и z≈.8. Это заранее передано основной задаче для согласования с симуляцией.
- Target есть у корня и непосредственно на colliders взаимодействий; `GetComponentInParent<HotelTarget>()` поддержан. У визуального сотрудника id player_ID нет игровой команды, он служит только отображению напарника.
- Проверить в первой runtime-сборке: отсутствие pink shaders, читаемость кириллицы/масштаб TextMesh, яркость ламп, высоту carry, raycast каждой цели, перенос и груз тележки, соседство FP-коллайдера с кроватями. Дальнейшую визуальную настройку делать по реальным кадрам сборки.
