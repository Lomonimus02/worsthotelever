# Worst Hotel Ever — Difficulty & Workload Scaling

## Separation

Difficulty Potential = how demanding Hotel can become.  
Workload = what is happening right now.

## Workload Sources

- Active Tasks
- Requests
- Complaints
- Dirty Rooms
- Queues
- Breakdowns
- Critical Problems
- Guest Count
- Distance
- Events

## Team Capacity

Depends on:

- Player Count
- Tools
- Layout
- Logistics
- Upgrades

## Workload Bands

- Low
- Healthy
- High
- Overload

Calm periods are valuable.

## Power Windows

Do not immediately counter every upgrade with harder pressure.

Player should feel stronger for a while.

## Soft Assistance

At very high Workload:

- reduce optional random requests
- reduce minor random breakdowns
- reduce Walk-ins
- lengthen Event cooldown

Do not erase logical existing problems.

## Signals

Director can observe:

- Task count
- queue length
- complaint resolution speed
- room readiness
- critical problems
- current Players

## Scale Drivers

- Hotel size
- occupancy
- guest complexity
- amenities
- infrastructure
- layout

## Event Budget

Events consume a pressure budget.

High-cost event should block another high-cost event.

## Stress Memory

Recent stress decays over time.

Avoid instant repeated peaks.

## Player Agency

Players can manage load through:

- closing rooms
- changing price
- rejecting Walk-ins
- disabling Amenities
- refusing planned Events

## Player Count

Scale frequency and composition, not the core rules.

## Endless Difficulty

Should become horizontally varied, not infinitely faster / denser.

## MVP Inputs

- Player Count
- Occupied Rooms
- Active Tasks
- Complaints
- Breakdowns
- Queue
- Critical Problems

## Core Question

**How much extra pressure can be added while the situation is still meaningfully solvable?**
