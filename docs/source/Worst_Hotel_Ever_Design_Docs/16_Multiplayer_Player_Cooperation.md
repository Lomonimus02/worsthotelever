# Worst Hotel Ever — Multiplayer & Player Cooperation

## Player Count

Target:

- 2–4 players

MVP balanced around 2.

## No Classes

All Players can:

- Check-in
- Clean
- Repair
- Deliver
- Move Guests
- Handle luggage

Roles should emerge naturally.

## Shared World

Players share:

- Hotel
- money
- Tasks
- items
- tools
- consequences
- progression

## Parallel Work

Core fantasy is simultaneous responsibility.

## Task Ownership

Tasks unowned by default.

Optional claim later.

## Physical Cooperation

- Item passing
- dropping
- Cart
- shared tools

Later:

- throwing
- heavy carry
- multi-step cooperative repair

## Avoid Artificial Dependency

Do not require two Players to stand on two buttons for routine Hotel work.

Co-op should come from workload and space.

## Collision

Soft interference.

Funny, but anti-grief.

## Shared Knowledge

If one Player discovers a known problem, team knowledge can update.

## Stations

Some stations create parallelism limits.

Upgrades can add second Reception station etc.

## Communication

MVP:

- simple ping

Later:

- Need Help
- I’ll Handle
- contextual pings

## Player Failure

No player death as core mechanic.

## Major Decisions

Shared Hotel decisions.

MVP can use host / simple purchase authority depending UX.

## Score

Avoid serious individual scoreboards.

Fun stats later are fine.

## MVP

- 2 Players
- shared world
- shared Tasks
- shared Items
- shared Tools
- shared Cash
- item pass/drop
- simultaneous Room work
- soft collision
- ping

## Alpha

- 3–4 Players
- drop-in
- better ping
- co-op carry

## Core Principle

Players cooperate because there is too much to do in one place at one time, not because the game assigns jobs.
