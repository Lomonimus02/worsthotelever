# Worst Hotel Ever — Room Customization & Furnishing

## Purpose

Customization should create ownership and gameplay, not full building simulation.

## Two Layers

### Visual Customization
- wall finish
- floor finish
- decor
- style

### Functional Furnishing
- Bed
- TV
- Desk
- Lighting
- Bathroom features
- Amenity slots

## Room Shell

Fixed physical shell.

No free wall / plumbing construction baseline.

## Slot-Based Functional Placement

Recommended slots:

- Bed
- TV
- Desk
- Main Light
- Bathroom
- Amenity
- Decor

## Beds

Separate:

- Quality
- Capacity

Examples later:

- Single
- Double
- Twin
- Family

## Equipment Expectations

No TV in Budget room may be acceptable.

Broken premium TV may be a serious complaint.

## Derived Room Category

Category should emerge from:

- quality
- capacity
- size
- amenities

rather than being manually selected.

## Quality vs Condition

Quality = what the item/room is.  
Condition = how healthy it currently is.

## Decor

Small / capped quality contribution.

Mostly identity / aesthetics.

## Renovation Timing

Major furniture changes during Preparation and ideally only in vacant Rooms.

## Integration

Furniture can:

- break
- require infrastructure
- affect cleaning
- influence Demand
- create requests
- increase Quality

## Better Gear Rule

Better furnishing should create genuine value.

It may also create more responsibility.

## MVP

- Basic Bed
- Comfortable Bed
- TV None / Basic
- a few visual finishes
- maybe Lamp variation

## Alpha

- Desk
- Minibar
- bed types
- bathroom upgrades
- decor
- more derived room categories
- templates

## Later

- freer decor
- themes
- family Rooms
- suites
- room naming/history

## Core Principle

Customization should make each Hotel feel owned while remaining compatible with navigation, cleaning and repair systems.
