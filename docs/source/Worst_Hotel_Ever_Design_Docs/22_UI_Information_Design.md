# Worst Hotel Ever — UI & Information Design

## Goal

UI helps Players understand chaos without turning the game into a spreadsheet.

## Three Layers

### World Information
What can be read directly in 3D.

### Immediate HUD
Urgent personal / team information.

### Management
Strategic Hotel overview.

## World-First

Examples:

- Dirty Bed looks dirty
- Leak visibly leaks
- Broken TV looks broken
- Guest visibly waits
- Room number is readable

## HUD

MVP:

- Time
- Cash
- Carried Item
- Important Notifications

Avoid permanent screen clutter.

## Task Presentation

Use:

- contextual world markers
- urgent notifications
- Overview

No giant quest list.

## Priority

- Critical
- Important
- Routine

Notifications only when priority changes or awareness matters.

## Door / Room Indicator

Show one dominant status.

Avoid stacking five icons.

## Guest Mood

Qualitative.

Requests / complaints readable with simple icons.

## Reservation UI

Only useful data:

- arrival
- party
- room need
- stay
- important requirements

## Hotel Overview

Sections:

- Rooms
- Guests
- Operations
- Schedule
- Hotel

MVP focus:

Rooms:
- Ready
- Occupied
- Needs Service
- OOS

Guests:
- Waiting
- Complaints

Operations:
- Important Problems

Schedule:
- Next Arrivals

## Root Cause UI

Example:

TV unavailable  
because  
Floor Power is Off.

## Ping

Simple multiplayer ping.

## Luggage

Ownership / Room target must be readable.

## Interaction

Context-sensitive.

## Color

Never rely on color alone.

Use icon / shape / text / animation too.

## Unknown vs Known

Problems can exist before team awareness.

## Reviews / Summary

Should explain causes, not only scores.

## Upgrade UI

Every upgrade should show:

- Benefit
- Responsibility

## Difficulty

Dynamic difficulty logic remains hidden.

## Core Principle

World communicates state.  
HUD communicates urgency.  
Overview communicates strategy.
